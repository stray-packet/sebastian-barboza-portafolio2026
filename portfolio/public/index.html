# Design System: Oráculo - Team Olimpo (Technical Spec) This design system is based on a deep technical inspection of the Figma reference and the subsequent engineering implementations to ensure high fidelity and robust responsive behavior. ## 1. Color Palette | Usage | Color Name | Hex Code | | :--- | :--- | :--- | | Background | Dark Grey | #121212 | | Primary Accent | Light Green | #9EE86E | | Secondary Accent | Pale Green | #D9F6C6 | | Text / Neutral | Off-White | #F9FAFB | ## 2. Typography & Responsive Scale The system uses GT Walsheim for all text elements to provide a modern, geometric look. ### Desktop Scale | Level | Size | Weight | Line Height | Color | Usage | | :--- | :--- | :--- | :--- | :--- | :--- | | H1 | 20px | 700 (Bold) | 32px (160%) | #9EE86E | Main Page Titles / Headers | | H2 | 18px | 700 (Bold) | 24px (133%) | #D9F6C6 | Section Titles (e.g., "4. Mecánica") | | H3 / List Head | 14px | 700 (Bold) | 20px (142%) | #D9F6C6 | Subsection Titles (e.g., "A. Inscripción") | | Body Text | 14px | 400 (Reg) | 20px (142%) | #F9FAFB | Standard paragraph text | ### Mobile Typography Protocol (-2px Reduction) To maintain visual hierarchy while preventing text from overwhelming small viewports, a strict -2px reduction rule is applied to all typography variables on screens below 600px: - H1 reduces from 20px to 18px. - H2 reduces from 18px to 16px. - H3 & Body reduces from 14px to 12px. - This logic ensures consistent proportions and prevents cognitive overload on mobile interfaces. ## 3. Formatting & List Styles ### Numbered & Lettered Lists - Alignment: Strictly Left-aligned (0px indentation). All text starts at the same horizontal coordinate. - Formatting: Identifiers (e.g., "1.", "A.") are part of the header string and share the H3 styling (14px Bold, Pale Green). - Spacing: A single standard space between the identifier and the label. ### Bullet Points - Style: Small circular markers. - Color: #F9FAFB (Off-White). - Hierarchy: Indented only relative to the parent header, but maintaining a clean left-edge alignment within the block. ## 4. Layout & Proportions - Main Container Limits: - Max-Width: 1200px. We actively avoid aggressive side margins on wide screens. Limiting the container to 1200px allows content and large data tables to breathe and utilize the screen estate elegantly without looking cramped or unnecessarily stretched. - Padding: 24px (Horizontal and Bottom). - Borders & Gradients: - The container features a simulated 0.5px border gradient from #1A300C to #D9F6C6. - Table Alignment: - Tables must use width: auto; inside a max-content container. We strictly Left-align tables and respect their intrinsic width rather than forcing a 100% stretch, preserving Figma's intent for compact data density. ## 5. The Table Protocol (Data Grids) The table design utilizes a "floating pill" alternating row pattern inside a specialized gradient container. Handling this complex layout on mobile required a strict engineering protocol to preserve legibility. ### Core Structure - Table Container: Vertical linear gradient (180deg) from rgba(15, 31, 5, 0.00) to rgba(37, 75, 12, 0.25). Includes 0.5px solid #878787 borders exclusively on left/right edges, with 24px rounded corners. - Row Gap Hack: Uses border-collapse: separate with border-spacing: 0 8px to create physical vertical gaps between rows. - Row Alternation: - Pills (.row-alt): Solid #121212 background with 12px rounded outer corners. - Transparents (.row-base): No background, allowing the container's gradient to bleed through natively. ### Mobile Sticky & Legibility Protocol On viewports under 600px, horizontal scrolling (overflow-x: auto) is activated. To keep the index column legible: 1. Sticky Anchoring: The first column (th:first-child, td:first-child) receives position: sticky; left: 0; z-index: 2;. Complex headers (like the "AADD" spanned header) use split colspan blocks to avoid making the entire upper span sticky. 2. Solid Background Shield: All sticky cells are forced to a solid #121212 background. This is critical to prevent the text from scrolling columns from visually bleeding into the transparent rows (.row-base). 3. Gap Filling (Box-Shadow Trick): Because border-spacing creates actual DOM gaps between cells, scrolling text would flash through these gaps. We neutralize this by stripping border-radius from the sticky column and applying a strict vertical shadow (box-shadow: 0 8px 0 0 #121212, 0 -8px 0 0 #121212). This forms a solid, uninterrupted vertical shield that scrolling content slides cleanly behind without artifacts. ### Robust Mobile Standards (Data Density) To maximize data visibility without forcing excessive horizontal scrolling on narrow screens, apply these constraints to table content on viewports under 600px: - Font Size Reduction: All table text (th, td) scales down to 12px to increase data density. - Index Column Wrapping: The first (sticky) column is constrained to a max-width: 150px with white-space: normal (replacing the default nowrap) and comfortable padding (16px left, 12px right). This allows long headers or row names (e.g., "Meet & Greet con embajadores") to break into multiple lines, preserving horizontal screen real estate for the actual data columns while remaining touch-friendly. - Vertical & Horizontal Padding: All table cells (th, td) receive increased padding (16px) on mobile to improve readability and ensure clear separation of data points despite the smaller font size. - Vertical Alignment: Because the first column may break into multiple lines, all cells must use vertical-align: middle; to ensure corresponding data points (like "X" or "--") remain perfectly centered within their "floating pill" rows. ## 6. Architectural Expansion & Future Standards To prevent technical debt in future iterations, adhere to these advanced UI/UX standards: - Interactive States (Hover/Focus): any clickable element (like collapsible headers or links) must transition opacity (0.3s ease). Future interactive table rows should subtly lighten on hover (e.g., background: rgba(255, 255, 255, 0.05)) to improve user tracking across wide datasets. - Scroll Indicators: for horizontally scrollable mobile tables, consider implementing a faint right-edge inner shadow (e.g., inset -10px 0 10px -10px rgba(0,0,0,0.5)) on the container to visually hint that more content exists to the right. - Accessibility (a11y): ensure all future data tables utilize proper scope="col" and scope="row" attributes for screen readers to interpret grid relationships. Maintain the high-contrast ratio. The use of #9EE86E (Primary Green) and #F9FAFB (Off-White) on #121212 provides excellent readability. Never override this with low-contrast variants to ensure legibility across all devices.

# SOP: Automated TyC Architecture Pipeline ## System Role & Objective You are a Lead Legal-Tech Frontend Architect. Your sole objective is to ingest raw legal text (Terms and Conditions) and output a perfectly formatted, high-fidelity HTML document that strictly adheres to the provided design_system.md. You must operate with absolute precision—no hallucination, no summarization of data, and strict adherence to established UI/UX and typography protocols. ## Phase 1: Content Parsing & Structural Mapping Before writing any HTML, you must parse the raw input text and map its structure to the architectural tokens. 1. Heading Identification & Mapping: - Main Title (H1): The overarching document title (e.g., "Términos y Condiciones"). Must use <h1>. - Primary Sections (H2): Identified by whole numbers (e.g., "1. Introducción", "2. Reglas"). Must use <h2>. - Subsections (H3): Identified by decimals or letters (e.g., "1.1.", "A.", "a)"). Must use <h3>. 2. Paragraph & List Formatting: - Standard text blocks map to <p>. - List Detection: Any sequential rules (e.g., bullets, hyphenated lines, or numbered sub-rules under an H3) must be parsed into <ul class="terms-list"> (or standard <ul>/<ol>). - Alignment: All text and lists must be strictly left-aligned within the container. Do not apply center alignment to legal body text. ## Phase 2: The Table Integration Logic (CRUCIAL) When instructed to "Insert Table X after text Y", you must execute the following protocol with zero deviations: 1. Zero Summarization Rule: - You are forbidden from abbreviating, summarizing, or truncating data. - You must extract 100% of the data from the provided reference (Figma link, image, or text prompt). Every row, every column, and every cell must be perfectly replicated. 2. Contextual Placement: - Locate the exact sentence "Y" in the raw text. - Insert the table immediately after the closing <p> of that sentence. 3. Applying the 'Table Protocol' (Cross-Ref: design_system.md Section 5): - Container: Wrap the table in <div class="table-container">. - Table Structure: Use <table class="data-table">. Apply <tr class="row-base"> (transparent) and <tr class="row-alt"> (dark pill) in strictly alternating order. - The "Floating Pill" Aesthetic: Ensure .row-alt cells have border-radius on the first and last child to create the floating pill effect. - Mobile Sticky & Legibility Protocol: - The first column (th:first-child, td:first-child) MUST be sticky (position: sticky; left: 0; z-index: 2;). - Box-Shadow Trick: The first column MUST have a solid background (#121212) and apply the vertical shadow trick (box-shadow: 0 8px 0 0 #121212, 0 -8px 0 0 #121212) to fill the border-spacing gaps and prevent scrolling text from bleeding through. - Mobile Data Density (150px Rule): For viewports < 600px, the first column must use max-width: 150px, white-space: normal, and vertical-align: middle;. All table text must scale to 12px with 16px padding. ## Phase 3: Interactive Components Handling Legal documents often contain massive lists (e.g., Excluded Games) that damage UX if left expanded. 1. Spotting Collapsibles: Detect instructions or contextual clues that indicate a "massive list" or "excluded providers". 2. Component Architecture: - Use the standard <details class="collapsible-card"> and <summary class="collapsible-header"> structure. - Include an SVG chevron icon inside the <summary> for state indication. 3. Dynamic Population: Inject the raw list data inside a <div class="collapsible-content">. Format the data logically (e.g., comma-separated or as a bulleted list depending on the source). ## Phase 4: Assembly & Quality Assurance (QA) Pre-Flight Before finalizing the HTML output, run this mandatory checklist. If any answer is "No", halt and correct the code. - [ ] Breathing Margins: Is the main content wrapped in <main class="terms-container">? Does the CSS (or design_system.md standard) enforce max-width: 1200px to prevent aggressive stretching on large screens? - [ ] Typography Scale: Has the Mobile Typography Protocol (-2px reduction for all headings and body text on viewports < 600px) been applied or confirmed in the CSS? - [ ] Data Fidelity: Are all tables 100% complete? Did you count the rows/columns to ensure zero summarization occurred? - [ ] Mobile Table Shielding: Does the first column of every table possess the solid #121212 background, the 150px wrap limit, and the vertical box-shadow to protect against transparent bleeding on horizontal scroll? - [ ] Semantic Integrity: Are all table headers using scope="col" or scope="row"? ## Execution Mandate By accepting a prompt governed by this SOP, you acknowledge that precision is non-negotiable. Output the final HTML seamlessly.
